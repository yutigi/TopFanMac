TopFan · Feature 002 · UI design treatment

One app, two surfaces.
Always visible; detailed on demand.

TopFan drives the MacBook’s fans harder than macOS would. The UI is deliberately small: an always-present menu-bar item for the glance, a dashboard window for the detail, and every number it shows comes straight from the daemon — never a guess. Values shown below are this machine’s real hardware facts: fan 0 spins 2317–6898 RPM, fan 1 spins 2502–7450 RPM.

P1

Menu bar — the glance

A status item pinned to the top of the screen, rendered by the existing (and already-tested) status formatter. Clicking it opens the control menu; the checkmark is the daemon’s authoritative state, updated by polling — never by which item was clicked.

P2

Dashboard — the detail

The main window, opened from the menu (⌘D), by double-clicking the status item, or by launching the app directly. Temperature leads; each fan is drawn against its own reported range — the two differ, and the UI never pretends otherwise. Everything updates on the 1–2 s poll; mode changes confirm only when the daemon confirms.

Design decisions

  • 2Per-fan ranges are printed. The two fans have different bounds; both arcs map duty within each fan’s own range (hardware-sourced, never constants).
  • 3Semantic color for temperature, not decoration: the accent is ice (cooling); heat turns the readout amber as load rises.
  • 4Endpoints emphasized, faint grid behind, area fill beneath the sparkline — a sensor read, styled like one.
  • 5Last-writer-wins is visible: buttons go pending and confirm from the polled daemon reply — the same honesty contract as the menu.
P3

Honest states

Three renderings, chosen by a pure function of the polled status. No modal errors, no spinners that never end — the UI degrades and recovers on its own.

Interaction contract

What the mockups above are bound to, from the feature spec — these are the acceptance points, not aspirations.

RuleSpecWhat the UI must do
One formatterFR-001Menu-bar title comes from the shared, tested status format — identical text in the dashboard header.
✓ is truthFR-005Every surface renders the daemon’s reply within one poll (1–2 s); local clicks never tick a checkmark.
ElevationFR-003Privileged modes use the system admin prompt (once per action); declining leaves state unchanged with a CLI fallback hint.
Self-recoveryFR-006Daemon gone → Unavailable within one poll; daemon back → live values, no user action.
Single instanceFR-008Second launch focuses the existing app — never two status items.
Headless logicFR-009Formatting, action mapping, and state derivation keep passing their tests with no display server.
